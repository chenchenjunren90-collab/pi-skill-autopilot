# Changelog

## 0.5.0

Safety and packaging.

- **Staged installs.** Skills are downloaded into `~/.pi/agent/skill-autopilot/staging/`, scanned, and only then moved into the skills directory.
- **Pre-activation scan** (`risk.ts`): 19 rules across five levels covering pipe-to-shell, base64 execution, reverse shells, destructive deletes, credential reads, env+network exfiltration, shell exec, dynamic eval, permission widening, privilege escalation, prompt-injection phrasing, network calls, env access, global installs, file writes and telemetry. Multi-line rules run against the whole file.
- **Two-stage consent on risk.** `critical` rolls back automatically; `high` triggers a second confirmation listing the offending lines; `medium`/`low` are recorded and surfaced in the hand-off note.
- **Pluggable stores** (`store.ts`): a `SkillStore` interface plus a registry. SkillHub is the built-in provider; `store` selects one and `/skill-autopilot stores` reports availability.
- **Generic plan extraction for plan/goal tools**: `extractStepsFromToolInput` walks tool arguments for step arrays, and plan files written to disk are parsed as plans.
- Bilingual demo GIFs (`assets/demo.gif`, `assets/demo.zh-CN.gif`) generated by `tools/render-demo.py`.
- Repo scaffolding: issue/PR templates, Code of Conduct, Security Policy, editorconfig, gitattributes.
- Readability fix: the score is now additive across slug/name/description tiers, so single-keyword queries are no longer discarded at the threshold.

## 0.4.0

Plan/goal plugin compatibility and packaging.

- **Structured plan extraction** (`tool_result` hook): reads plan/goal tool arguments generically, so `set_goal_tasks` (pi-goal-x), `create_goal`, `todo_write`, `update_plan` and similar tools all work.
- **Plan-file extraction**: writing to `PLAN.md`, `.pi/tasks.json`, `roadmap.md`, … is parsed as a plan.
- **Configurable tool matching** via `planToolPattern` (default `plan|goal|task|todo`); read-only `get_*` tools are ignored.
- **Unified hand-off** through `pi.sendMessage`, so the step→`SKILL.md` mapping reaches the model from every trigger.
- **Scoring fix**: relevance is now additive across slug/name/description (previously a token that hit both slug and name skipped the description tier and scored 5 instead of 6, which silently dropped single-keyword matches).
- **Capability over domain**: `esg`, `financial`, `academic` are treated as domain words, not capabilities, and the earliest-mentioned capability in a step wins.
- New CJK-aware step length threshold.
- Packaging: LICENSE, CI, tsconfig, CHANGELOG, bilingual README, publish metadata.

## 0.3.0

Plan-driven provisioning.

- `turn_end` hook parses `Plan:` / `计划：` sections from the assistant message, maps every step to a store skill, and confirms the whole batch once.
- Sequential install with a status-bar progress indicator.
- `/skill-autopilot plan <path>` runs the pipeline against a plan file.
- Step-level dedupe: a skill needed by several steps is installed once, at the earliest step.
- Plan signature dedupe: the same plan is not asked about twice.
- `planEnabled`, `planMinScore`, `maxPlanInstalls` settings.

## 0.2.0

Confirmation instead of automatic installation.

- `mode` is now `confirm | suggest | off`; the `auto` mode was removed and old configs migrate automatically.
- One confirmation per turn, then the original task continues in the same turn.
- Single candidate → yes/no dialog; multiple candidates → selection dialog with a skip option.
- Declined skills are not offered again in the session.
- `skill_ensure` also requires confirmation, and refuses to guess when no dialog is available.
- Removed dead code and unused imports.

## 0.1.0

Initial version.

- `before_agent_start` capability detection from file extensions and an EN/CN keyword lexicon.
- Local store catalog built from SkillHub showcase sections, grown by live searches.
- Quantified relevance scoring with an installed-skill scan across user, project, `.agents`, and npm package skill directories.
- `skill_ensure` tool and `/skill-autopilot` command.
